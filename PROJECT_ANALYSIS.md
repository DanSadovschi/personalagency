# Анализ проекта personalagency

Дата: 2026-02-24

## 1) Краткий обзор

Проект — статический маркетинговый сайт агентства **WebOrb** на **Eleventy (11ty)**.

- Сборка и дев-режим реализованы через `npm run build` и `npm run dev`.
- Исходники находятся в `src/`, результат сборки — `_site/`.
- Деплой ориентирован на Vercel.

## 2) Текущая архитектура

### Технологии

- Генератор: `@11ty/eleventy`.
- Шаблоны: `*.njk`, `*.html`, `*.md`.
- Фронтенд: ванильные CSS/JS без фреймворков.

### Структура контента

- Главная и служебные страницы: `src/index.njk`, `src/work.njk`, `src/projects.njk`, `src/offer.html`, `src/starter.html`.
- Кейсы/портфолио: папка `src/projects/` (`.md` + `projects.json`).
- Локальные SEO-страницы по городам: `src/locations/web-design-[city.slug].njk` + данные `src/_data/cities.json`.
- Общий layout: `src/_includes/layouts/base.njk`.

### Конфигурация сборки

- `.eleventy.js` копирует статику из `src/css`, `src/js`, `src/img`, `src/favicon.svg`.
- `vercel.json` нацелен на сборку `npm run build` и артефакт `_site`.

## 3) Сильные стороны

- **Простая и предсказуемая сборка**: минимум зависимостей, быстрый билд.
- **Хороший SEO-каркас**: canonical/OG/Twitter мета-теги в базовом layout.
- **Масштабируемый локальный SEO**: генерация страниц по городам из JSON-данных.
- **Контентно-ориентированная структура**: проекты как Markdown-контент.

## 4) Риски и проблемные зоны

1. **Секрет в репозитории**  
   В `src/_data/site.json` хранится `web3formsKey`. Для публичного репозитория это риск утечки/злоупотребления ключом.

2. **Неоднозначность со статическими файлами в корне**  
   В проекте есть `css/styles.css` и `js/main.js` в корне, а также `src/css/styles.css` и `src/js/main.js`. Сборка использует `src/*`; дубли в корне могут вводить в заблуждение и устаревать.

3. **Нет автоматизированных проверок качества**  
   В `package.json` отсутствуют скрипты тестов/линтинга/форматирования, из-за чего регрессии ловятся только вручную.

4. **Потенциально тяжёлые медиа**  
   Каталог `src/img` занимает ~19MB. Для лендингов это может ухудшать LCP/CLS при слабой сети, если не везде используется правильная оптимизация загрузки.

5. **Нет формализованной документации**  
   Не хватает README с командами запуска, контентной моделью, правилами добавления кейсов/городов.

## 5) Приоритетные улучшения

### Высокий приоритет (1–2 дня)

- Перенести `web3formsKey` в переменные окружения (или serverless proxy), ротировать существующий ключ.
- Удалить/архивировать дубли `css/` и `js/` в корне либо явно задокументировать их назначение.
- Добавить минимальные quality-gates: `npm run lint` (HTML/CSS/JS), `npm run check` (проверка сборки).

### Средний приоритет (2–5 дней)

- Добавить README с:
  - быстрым стартом,
  - процессом добавления проекта в `src/projects/`,
  - процессом добавления города в `src/_data/cities.json`.
- Включить базовую оптимизацию изображений (responsive sizes/lazy loading/современные форматы на ключевых блоках).
- Ввести простую схему нейминга и проверку broken links.

### Низкий приоритет

- Разделить большой CSS на секции/модули по страницам.
- Добавить smoke e2e (например, Playwright: главная, projects, work, 1 city page).

## 6) Проверки, выполненные при анализе

- Сборка проекта проходит успешно: `npm run build`.
- Подтверждена конфигурация Eleventy passthrough-копирования статики.
- Подтверждён Vercel pipeline (`buildCommand`, `outputDirectory`).

## 7) Итог

Проект в рабочем состоянии и хорошо подходит для быстрого контентного развития через Eleventy. Главные задачи на ближайший цикл: **безопасность ключей**, **уборка дублирующихся ассетов**, **введение минимальных проверок качества и документации**.
